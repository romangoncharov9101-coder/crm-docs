# Поля: типы и настройки

### 4.1. Типы полей
| Тип | Что это | Примечания |
|---|---|---|
| **Текст** | Обычная строка | Можно включить проверку на дубли |
| **Email** | Почта | Проверяется формат; дубли включены по умолчанию |
| **Телефон** | Номер | Дубли включены по умолчанию |
| **Многострочный текст** | Большое поле для заметок | |
| **Список** | Выбор из заданных вариантов | Варианты задаёте вы; можно назначать цвета |
| **Дата** | Только дата | Фильтруется диапазоном от — до |
| **Дата и время** | Дата с временем | Используется календарём |
| **Деньги** | Число с валютой | Только по таким полям считаются суммы и средние |
| **Связь** | Ссылка на одну запись другой сущности | |
| **Связь (несколько)** | Ссылка на несколько записей | Может работать как Исполнители |
| **Цвет** | Цветовая метка | Оформление, а не данные |

Три поля создаются системой и вручную не добавляются: **Ответственный**, **Дата создания**, **Дата изменения**.

### 4.2. Общие настройки любого поля
**Название** - как поле подписано в интерфейсе.
**Slug** - техническое имя латиницей. Формируется автоматически из названия.
**Порядок** - число, определяющее позицию поля в форме и в таблице. Меньше - выше.

### 4.3. Галочки-настройки
| Настройка | Что делает |
| --- | --- |
| **Показывать в таблице** | Поле становится колонкой в системе записей |
| **Показывать в форме** | Поле появляется при создании и редактировании записи |
| **Обязательное** | Без значения запись не сохранится |
| **Использовать на дашборде** | Обязательно для виджетов. Без неё поле не появится в конструкторе виджетов ни как метрика, ни как разрез, ни как фильтр |
| **Массовое редактирование** | Поле можно менять сразу у нескольких выделенных записей |
| **Проверять на дубли** | Записи с одинаковыми значениями помечаются как дубли (только текст, email, телефон) |
| **Мультиселект в фильтре** | В фильтре можно выбрать сразу несколько значений |
| **Быстрое копирование** | Рядом со значением появляется кнопка "скопировать" - в таблице и на карточке записи |
| **Блок на карточке связанной записи** | Только для типа "Связь". На карточке той записи, на которую ссылается поле, появится блок со всеми связанными записями и кнопками добавить/удалить |
| **Доступ ответственному** | Только для "Связь". Ответственный за связанную запись увидит эту запись, даже если в ней самой ответственным назначен кто-то другой |

Для поля типа **Цвет** часть галочек недоступна: по цвету нельзя фильтровать, считать на дашборде и менять массово. Цвет - это оформление.

### 4.4. Настройка отдельных типов
**Список** Добавляет строки вида "Подпись -> Значение". Значение формируется транслитерацией автоматически; если вы правите его вручную, авто-подстановка отключается - так правка подписи не сломает уже существующие данные.
**Деньги** Выбираете символ валюты кнопкой или вводите свой, например "USD".
**Связь и Связь (несколько)**
- *Связанная сущность* - куда ведет ссылка. Связь на саму себя запрещена.
- *Отображать по полю* - какое поле связанной записи показывать вместо её номера (в таблице, в форме, в поиске).
- Связь — ровно одна запись. Связь (несколько) — сколько угодно, это связь многие ко многим.
**Поле исполнителей** Особый режим для "Связи (несколько)" на сущность "Пользователи". Включив галочку "Поле исполнителей", вы получите:
- оповещения исполнителям о назначении, изменениях и комментариях;
- руководитель команды может назначать только своих участников;
- рядовой сотрудник может назначить только себя и не меняет состав.
Такое поле у сущности может быть только одно.

### 4.5. Смена типа существующего поля
Если вы меняете тип и в записях уже есть значения, которые новому полю не подходят, система не сохранит молча. Появится окно: сколько записей затронуто и какие значения мешают. Варианты:
- **Дополнить** - для "Списка" недостающие значения добавятся в варианты; для "Связи" по текстовым значениям создадутся записи в связанной сущности, а тексты заменятся ссылками. Данные сохраняются.
- **Удалить конфликтные значения** - несовместимые значения очистятся, остальные останутся.
- **Отменить** - ничего не меняется.

Переход между "Связь" и "Связь (несколько)" конфликтом не считается: значения конвертируются сами (одно значение -> список из одного; обратно берётся первое).

### 4.6. Удаление поля
Удалить можно только поля, созданные вами. Системные - нельзя. По умолчанию сохранённые значения остаются в базе как резервные, поле просто исчезает из интерфейса.
